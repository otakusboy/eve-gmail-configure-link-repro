# Gmail Configure link: component reproduction

The Gmail integration's `[Configure](#configure)` link is rendered with
`target="_blank"`. A normal click opens another tab instead of navigating the
current page to its Configure section.

**Verification scope:** this is an isolated reproduction using an unchanged
snapshot of eve's actual Markdown component and the exact Gmail paragraph. It
server-renders the component and checks the resulting link in a real browser.
It does **not** run the full Next.js website or hydrate React in the browser.
Production-site and full-site end-to-end verification remain outstanding.

## Run

Use Node.js 24 and npm. Install dependencies and the matching headless browser:

```sh
npm ci
node node_modules/playwright-core/cli.js install chromium --only-shell
npm run reproduce
```

The browser download is a one-time prerequisite. No Vercel credentials, Gmail
account, API keys, model calls, or deployment are needed.

`npm run reproduce` verifies source snapshot checksums, renders the actual component,
then serves the generated HTML on an ephemeral local port. Chromium clicks the
Configure link at 320px, 390px, and 1280px viewport widths and compares it with a
normal fragment-link control. The browser and server close when the command ends.

**Exit 0 means the bug was successfully reproduced**, including a passing control.
If the link no longer opens another tab, or setup fails, the command fails.

| Link | Expected reproduction result |
| --- | --- |
| Configure from the real component | Two tabs; original URL has no fragment; new tab has `#configure` |
| Native fragment control | One tab; original URL changes to `#configure` |

To click the links manually:

```sh
npm run preview
```

Open the printed localhost URL, click **Configure** in the Gmail paragraph, then
compare **Native fragment control**. Stop the preview with Ctrl+C.

For a pre-installed compatible Chromium, set `CHROMIUM_PATH` instead of downloading
one. The standard commands above use Playwright's matching headless shell.

## Evidence and source provenance

- `evidence-node24.txt`: clean-install reproduction on Node.js 24.
- `evidence.txt`: initial standalone run on Node.js 26 using an existing Chromium.
- `browser-evidence.json`: structured output from the most recent browser run.
- `index.html`: generated output, rebuilt by `npm run render`.
- `SOURCE-PROVENANCE.json`: source paths, audited commit, and snapshot checksums.

Audited source: [`vercel/eve` at a5328b4](https://github.com/vercel/eve/tree/a5328b4482812da9cf97e7ad90df363950627032).

`src/markdown.tsx` and `src/lib/analytics/events.ts` are byte-for-byte snapshots
from that commit. The fixture is the exact paragraph from `data.ts:1287`.
The surrounding HTML and native control belong to this reproduction. The
Configure destination uses the same `id="configure"` as the real detail page;
its explanatory text is fixture content.

The direct frontend dependency versions match the audited docs app. Next.js and
Geistdocs are dependencies of the original component; this reproduction does not
start a Next.js server. `tsx` resolves the component's existing `@/lib/...` alias
through this repository's tsconfig. Analytics callbacks are not hydrated or run.
Upstream Apache-2.0 LICENSE and NOTICE are included.

This is a website-component reproduction, so it uses source snapshots rather than
an unrelated agent generated by `eve init`.

## Full-site verification limit

The original local docs preview could not be exercised successfully: Turbopack
encountered module resolution errors, and the webpack preview encountered a route
redirect loop. Those setup failures are not the bug reported here. Neither their
cause nor a production impact is claimed.

The source component's emitted `_blank` attribute and its native browser behavior
are confirmed. This harness does not establish hydration behavior, production
routing, layout, keyboard-modified clicks, or behavior in other browsers.
